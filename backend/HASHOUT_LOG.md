## v0.16.0 entries

### templates/conformance.json, services/templates.py · the Function conformance template
- refers-to: SOURCES, names_of, computed_preview, summary; Store.create
- kind: explainer

`conformance.json` is generated by `tools/conformance_template/build.py` in the planning sidecar from the conformance run's `ms_examples.json` and `ms_results.json`, and is not edited by hand. It holds one workbook:
- A Summary sheet counts cases, compared cases and matches per table, with a total.
- Then one sheet per Microsoft example table. The page's data is at A1; from row 2 come the formula (AA), the page result (AB), a match test (AC), a note (AD) and the page's description (AE).
- The match test is `ERROR.TYPE` equality for an error result, `ROUND` at the page's decimals for a number, `=` for a date or TRUE/FALSE, and `EXACT` for text, each inside `IFERROR(..., FALSE)`. These are the conformance runner's rules, so the workbook and the runner agree case for case (checked: 181 of 186 in both).

Templates may now carry `names` (`[name, refers]` pairs), defined after the sheets load; the LAMBDA page's four Name Manager definitions use this. A template whose preview area holds formulas gets its preview computed by the engine over the whole template (cross-sheet formulas included), cached per template. The other templates hold no formulas there and keep the raw preview.

## v0.12.0 entries

### services/store.py, routers/workbooks.py · workbook names
- refers-to: Store._write, Store._load, Store.get, Store.set_name; PUT /api/workbooks/{id}/names
- kind: explainer

`workbook.json` gains a top-level `names` list of `[name, refers]` pairs, written from the engine's `names()`. A file without it opens as before. On open, each name is defined after every sheet's cells are loaded; a name the engine refuses is skipped rather than failing the whole file. `PUT /api/workbooks/{id}/names` with `{name, refers}` defines or replaces a name, and an empty `refers` removes it. A name the engine rejects is a 422 carrying the engine's reason. `GET` returns the list so the window can load it into its own engine.

### services/store.py · one engine per open workbook
- refers-to: app/services/store.py :: Store._load, edit
- kind: rationale
- logged: v0.3.0 · 2026-10-21

The engine process keeps each opened workbook in a `formcel_engine.Workbook` (the Rust core) and applies the window's edits with `load`, which records no undo step: history lives in the window. Every edit batch rewrites the file; the window batches keystrokes for 400 ms.

### services/store.py · ids and paths
- refers-to: app/services/store.py :: Store.path
- kind: warning-context
- logged: v0.3.0 · 2026-10-21

Ids are 12 hex characters; `path` refuses anything that is not alphanumeric, so no request can name a file outside `Workbooks` or `Trash`. Checked: `..%2F..%2Fetc` and `zz..zz` both answer 404.

### services/store.py · listing, not list

## v0.7.0 entries

### Formulas are saved as typed
- refers-to: app/services/store.py :: Book.preview, _write, get; engine Workbook.cells, values
- kind: explainer
- logged: v0.7.0 · 2026-10-21

`Workbook.cells(sheet)` now returns each cell's input (a formula as `=...`), so `.fcel` files keep formulas and the window gets them back on open; the engine on each side recalculates. `Workbook.values(sheet)` returns computed results and feeds the Home thumbnails. Files written before v0.7.0 hold display text only and open unchanged. The window sends the formula text for every changed formula cell, so edits never replace a formula with its result on disk.

## v0.4.0 entries

### services/store.py · sheet views in the file
- refers-to: app/services/store.py :: Book.views, fit_views, _write, _load, sheet_op
- kind: explainer
- logged: v0.4.0 · 2026-10-21

Each sheet in `workbook.json` is now `{name, view, cells}`. The view holds what the window needs to show the sheet as it was left: row and column sizes, hidden rows and columns, frozen rows and columns, zoom and the tab colour. Files from v0.3.0 have no `view` and load with an empty one. `fit_views` keeps the list the same length as the sheets after any add, delete or move, and `sheet_op` moves a sheet's view with the sheet. A PATCH of a view merges into what is stored, so the window can send only the part it changed.

### services/store.py · shift
- refers-to: app/services/store.py :: Store.shift, routers/workbooks.py :: ShiftIn
- kind: rationale
- logged: v0.4.0 · 2026-10-21

Inserting or deleting rows or columns is sent as the operation (`POST /shift` with sheet, rows, at, n, insert), not as the thousands of cell edits it causes, and the engine process runs the same Rust shift as the window. The window chains the shift after any pending cell save, so the two never arrive in the wrong order.

### Threads
- refers-to: app/services/store.py :: Book.lock
- kind: warning-context
- logged: v0.4.0 · 2026-10-21

FastAPI runs these `def` routes on a thread pool, so one workbook is reached from several threads. Every call goes through `Book.lock`. Before v0.4.0 the Rust class refused cross-thread use and, with `panic = "abort"`, took the process down on the first request that landed on a new thread (see engine HASHOUT_LOG, #py). Checked after the fix: eight threads reading one workbook all answered.

## app/services/store.py {#store-formats}

### Formats in the file
- refers-to: app/services/store.py :: _write, _load, get, set_formats; app/routers/workbooks.py :: set_formats
- kind: explainer
- logged: v0.18.0 · 2026-10-21

Each sheet in `workbook.json` gains `formats`, a list of `[row, col, code]`. Loading applies the formats before the cells, so a cell under `@` reads `007` back as text and not as 7. `POST /api/workbooks/{id}/formats` takes the same body as `/cells`; an empty code clears that cell's format. The window sends formats before the cells of the same change for the same reason.

### Styles in the file
- refers-to: app/services/store.py :: _write, _load, get, set_formats(styles=True); app/routers/workbooks.py :: set_styles
- kind: explainer
- logged: v0.19.0 · 2026-10-21

Each sheet also gains `styles`, a list of `[row, col, style]` in the engine's canonical style text. `POST /api/workbooks/{id}/styles` takes the same body as `/formats` and shares its handler; an empty style clears the cell. Row heights grown for wrapped or large text are saved through the sheet's view like any other row height.

### Merges in the file
- refers-to: app/services/store.py :: _write, _load, get, set_merges; app/routers/workbooks.py :: set_merges, MergesIn
- kind: explainer
- logged: v0.20.0 · 2026-10-21

Each sheet gains `merges`, a list of `[r0, c0, r1, c1]`. `PUT /api/workbooks/{id}/merges` replaces a sheet's whole list; the window sends it after any change that touched merges, including undo, because the engine process only replays inserts and deletes and would otherwise keep merges an undo restored.

### Theme and cell styles in the file
- refers-to: app/services/store.py :: _write, _load, get, set_look; app/routers/workbooks.py :: set_look, LookIn
- kind: explainer
- logged: v0.21.0 · 2026-10-21

`workbook.json` gains `theme` (the theme text) and `cellStyles` (one line per named style). They are loaded before the sheets so number formats from styles apply as cells load. `PUT /api/workbooks/{id}/look` replaces either or both. A file from before v0.21.0 opens with the FormCel theme and the built-in styles.

### Conditional formatting rules in the file
- refers-to: app/services/store.py :: _write, _load, get, set_rules; app/routers/workbooks.py :: set_rules, RulesIn
- kind: explainer
- logged: v0.22.0 · 2026-10-21

Each sheet gains `rules`, one line per rule in precedence order. `PUT /api/workbooks/{id}/rules` replaces a sheet's list; lines that do not parse are dropped on load rather than failing the workbook.

### Links in the file
- refers-to: app/services/store.py :: _write, _load, get, set_links; app/routers/workbooks.py :: set_links
- kind: explainer
- logged: v0.23.0 · 2026-10-21

Each sheet gains `links`, a list of `[row, col, target]` for links held by cells; links from HYPERLINK formulas live in the formulas. `POST /api/workbooks/{id}/links` takes the `/cells` body; an empty target removes the link.
