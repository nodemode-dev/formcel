## v0.40.6 entries

### Windows install: failures stop it, a missing Tesseract does not
- refers-to: oc_install.bat; ../formcel_oc_install.bat; ../frontend/oc_install.bat
- kind: rationale
- logged: v0.40.6 · 2026-10-30

`oc_install.bat` stops with exit code 1 when the venv, its activation, the pip upgrade, the requirements, the engine module or its import fails, and ends with `exit /b 0` after the Tesseract checks. Tesseract is optional (only Data from a picture needs it), and before this the last command was `where winget`, which leaves ERRORLEVEL 1 on a machine with neither Tesseract nor winget, such as the Windows build runner. The batch returned that 1, `pushd backend && call oc_install.bat && popd` in `formcel_oc_install.bat` skipped `popd` and the window install, and `build_app.bat` stopped. pip runs as `python -m pip` so the venv's own interpreter is the one that installs. `formcel_oc_install.bat` now runs each side with `pushd`, `call`, then `if errorlevel 1` to `popd` and `exit /b 1`, so a failed side restores the folder and stops the install with a non-zero code, and it ends with `exit /b 0`. `frontend/oc_install.bat` stops when `npm install` or `engine\build_wasm.bat` fails and ends with `exit /b 0`.

## v0.16.0 entries

### templates/conformance.json, services/templates.py · the Function conformance template
- refers-to: SOURCES, names_of, computed_preview, summary; Store.create
- kind: explainer

`conformance.json` is generated by `tools/conformance_template/build.py` in the planning sidecar from the conformance run's `ms_examples.json` and `ms_results.json`, and is not edited by hand. It holds one workbook:
- A Summary sheet counts cases, compared cases and matches per table, with a total.
- Then one sheet per Microsoft example table. The page's data is at A1; from row 2 come the formula (AA), the page result (AB), a match test (AC) and a note (AD). Since v0.39.3 there is no column AE: the page's own description is not copied.
- The match test is `ERROR.TYPE` equality for an error result, `ROUND` at the page's decimals for a number, `=` for a date or TRUE/FALSE, and `EXACT` for text, each inside `IFERROR(..., FALSE)`. These are the conformance runner's rules, so the workbook and the runner agree case for case (checked: 181 of 186 in both).

Templates may now carry `names` (`[name, refers]` pairs), defined after the sheets load; the LAMBDA page's four Name Manager definitions use this. A template whose preview area holds formulas gets its preview computed by the engine over the whole template (cross-sheet formulas included), cached per template. The other templates hold no formulas there and keep the raw preview.

## v0.12.0 entries

### services/store.py, routers/workbooks.py · workbook names
- refers-to: Store._write, Store._load, Store.get, Store.set_name; PUT /api/workbooks/{id}/names
- kind: explainer

`workbook.json` gains a top-level `names` list of `[name, refers]` pairs, written from the engine's `names()`. A file without it opens as before. On open, each name is defined after every sheet's cells are loaded; a name the engine refuses is skipped rather than failing the whole file. `PUT /api/workbooks/{id}/names` with `{name, refers}` defines or replaces a name, and an empty `refers` removes it. A name the engine rejects is a 422 carrying the engine's reason. `GET` returns the list so the window can load it into its own engine.

## app/services/store.py {#store-formats}

### Formats in the file
- refers-to: app/services/store.py :: _write, _load, get, set_formats; app/routers/workbooks.py :: set_formats
- kind: explainer
- logged: v0.18.0 · 2026-10-21

Each sheet in `workbook.json` gains `formats`, a list of `[row, col, code]`. Loading applies the formats before the cells, so a cell under `@` reads `007` back as text and not as 7. `POST /api/workbooks/{id}/formats` takes the same body as `/cells`; an empty code clears that cell's format. The window sends formats before the cells of the same change for the same reason.

Each sheet also gains `styles`, a list of `[row, col, style]` in the engine's canonical style text. `POST /api/workbooks/{id}/styles` takes the same body as `/formats` and shares its handler; an empty style clears the cell. ### Opening and saving .xlsx
- refers-to: app/services/xlsx/reader.py :: read; writer.py :: write; styles.py :: tokens_in, apply_out, colour_in, colour_out; theme.py :: theme_in, theme_out; formulas.py :: from_file, to_file; app/services/store.py :: import_xlsx, export_xlsx; app/routers/workbooks.py :: import_file, export_xlsx
- kind: explainer
- logged: v0.25.0 · 2026-10-21

`POST /api/import?name=File.xlsx` takes the file's bytes as the body (no multipart, so no extra dependency), reads it with openpyxl (MIT) and makes a new workbook; the answer is the workbook's meta plus `notes`, one line per kind of content left out with its count. `GET /api/workbooks/{id}/export.xlsx` writes the workbook as .xlsx.

Brought in and written out: sheets and their order, values (numbers, text, TRUE and FALSE, errors), formulas, number format codes, fonts, fills, borders, alignment, indent, wrap and rotation, the workbook theme's colours and fonts, cell styles (built-in and the workbook's own), merges, links, workbook names, freeze panes, column widths, row heights, hidden rows and columns, outline levels, zoom and tab colours. Left out for now and listed in the notes: conditional formatting, data validation, comments, pictures, charts, pivot tables, what-if data tables, chart sheets, print areas and hidden names, and names scoped to one sheet. Tables come in as plain ranges.

Formulas: files write newer functions with a prefix, `_xlfn.` and for FILTER, SORT and PY `_xlfn._xlws.` (MS-XLSX 2.2.3; the list is `future.json`, generated by `tools/xlsx_future/build.py` in the planning sidecar). XMATCH is not on that page; FormCel adds it. LET and LAMBDA parameter names are written as `_xlpm.name`, which is what Excel writes; no Microsoft page found says so, so it is FormCel's reading. Prefixes are removed on the way in and added on the way out, never inside quoted text. An array formula comes in as one formula in its first cell, which spills.

Values: text is written with a leading apostrophe only when FormCel would otherwise read it as something else (`formcel_engine.reads_as_text`), and never under a format with `@`. Dates come in as serial numbers with their code. The built-in short date (format 14, which openpyxl names `mm-dd-yy`) comes in as `m/d/yyyy`, FormCel's choice for the system short date the code stands for. Formats FormCel picked up from typing (a typed date or `5.50%`) are written as codes (`auto_formats`).

Sizes: a column `width` is in characters of the default font; 7 pixels each is the rule used both ways, so 8.43 characters (stored as about 9.14) is 64 pixels. Columns without a width get the file's default width up to column Z or the last used column. Row heights are points, 0.75 to the pixel. FormCel's own default column (100 px) and row (24 px) are written as the sheet defaults.

Styles: theme colours map from the file's index order (lt1, dk1, lt2, dk2, accents) to FormCel's slots; a tint becomes a percentage. Cell styles are written as named styles (Accent 1 as Accent1) and a cell keeps its own formatting over its style; on the way in, formatting a cell shares with its named style is dropped so the cell says `cs:Name` plus what differs. The default font of the file (font 0) counts as no font setting.

On export the full calculation flag is set, so Excel recalculates on open; cached values are not written. From v0.28.0, `@x` is written as `_xlfn.SINGLE(x)` (MS-IMPLICIT: older Excel shows the operator as `_xlfn.SINGLE()`) and `A1#` as `_xlfn.ANCHORARRAY(A1)`, and both are read back the other way. ANCHORARRAY is not on the Microsoft pages read (MS-SPILLOP, MS-IMPLICIT, MS-DANONDA, MS-XLSX functions); it is the name FormCel understands Excel to write. Text kept under merged cells is not written, since a merged cell shows only the contents of its upper-left cell (MS-MERGE).

### Conditional formatting in .xlsx
- refers-to: app/services/xlsx/cf.py :: rules_in, rules_out, dxf_tokens, dxf_out; reader.py :: read; writer.py :: write; store.py :: import_xlsx
- kind: explainer
- logged: v0.26.0 · 2026-10-21

Every FormCel rule kind maps to a rule type in the file: cellIs (with its eight operators), containsText, notContainsText, beginsWith, endsWith, timePeriod, duplicateValues, uniqueValues, top10, aboveAverage, the four blank and error types, expression, colorScale, dataBar and iconSet (3 arrows, 3 traffic lights, 3 flags, 3 symbols, 4 arrows, 5 arrows). Rules are read in priority order, so FormCel's top rule is the file's priority 1, and written in FormCel's order, which openpyxl numbers 1, 2, 3. A rule over several ranges becomes one FormCel rule per range, with formula references moved by `formcel_engine.offset`. A rule's format is a differential style: in the file a solid fill's colour sits in `bgColor`, not `fgColor`.

A cellIs value is a number, a quoted text or a formula; it comes in as the number, the text, or `=formula`. Text, date and blank rules carry a formula in the file as well as their type; FormCel writes `NOT(ISERROR(SEARCH("t",A1)))` and the like for the first cell of the range, and for dates the FLOOR, ROUNDDOWN, EDATE and WEEKDAY forms. These are the forms Excel writes as FormCel understands them; no vendor page gives them, and they are not read back (FormCel reads the type).

Left out with a note: rule types FormCel does not have, icon sets FormCel does not draw, average rules with standard deviations or "or equal", and scales or bars with theme colours. Icon cut-offs that are not percents become even steps, and scale points from formulas become lowest or highest, each with a note. Excel's data bar extension (negative bar colour, axis) is not read; openpyxl drops it.

Checked: all 19 rule forms in `tools/checks/xlsxcheck.py` come back unchanged after write and read. After LibreOffice 24.2 opens and re-saves the file, 18 of 19 come back unchanged. LibreOffice drops Stop If True, so that rule comes back without it.

### CSV, TSV and text files
- refers-to: app/services/csvio.py :: decode, sniff, rows_of, guess, preview, cells, write; store.py :: import_csv, export_text; app/routers/workbooks.py :: preview_file, import_file, export_text
- kind: explainer
- logged: v0.26.0 · 2026-10-21

`POST /api/import/preview?name=&delimiter=` reads a .csv, .tsv or .txt body and answers the separator, the encoding, the row count, a guess for each column and the first 12 rows. `POST /api/import?name=&delimiter=&text=0,3` makes the workbook; the columns listed in `text` keep every value as written. Separator sniffing is ported from form.md 0.46.0 (`internal/collection/csv.go` sniffDelimiter: the most common of comma, semicolon, tab and vertical bar in the first line), with .tsv always tab. Encoding: a UTF-8 or UTF-16 byte order mark, else UTF-8, else Windows-1252, which is named in the notes.

Values are read as if typed, so numbers, dates, percents and TRUE or FALSE become values. A column is suggested as Text when any value is a digit string with a leading zero or more than 15 digits, the values a General column would change. A value starting with `=` stays text and is counted in the notes: opening a file should not run what it contains.

Export writes the sheet's values as shown, UTF-8 with a byte order mark, CRLF line ends, comma or tab. One sheet per file; the file is named after the workbook, and the sheet when its name differs.

### OpenDocument spreadsheets (.ods)
- refers-to: app/services/ods/__init__.py :: read, write, _cell, _cell_style, _cell_xml; ods/formulas.py :: from_file, to_file, range_in; ods/numfmt.py :: to_style, from_style; store.py :: import_xlsx (kind ods), export_ods
- kind: explainer
- logged: v0.27.0 · 2026-10-21

FormCel reads and writes .ods itself, with the standard library's zipfile and ElementTree; no ODF library is added. Read: sheets, values by `office:value-type` (float, percentage, currency, date, time, boolean, string), formulas, number formats from the data styles in content.xml and styles.xml, cell formatting from automatic cell styles (bold, italic, underline, strike, size, font, colours, borders, alignment, wrap, indent, rotation), merges, links in text, column widths and custom row heights, hidden rows and columns, named ranges and named expressions. Repeated rows and cells are expanded up to 1,000 copies. Left out with notes: conditional formatting, comments; frozen panes (in settings.xml) are not read.

Write: one automatic cell style per distinct style and format, data styles converted from Excel codes (numbers, percent, currency, scientific, dates and times, elapsed hours, text). Codes with sections, colours, conditions, fractions, scaling or quoted text are written in a simpler form. Formula cells carry their current result, so a reader that does not recalculate shows the right value. Errors are written as text with `calcext:value-type="error"`, as LibreOffice writes them, and read back as errors. Conditional formatting is not written to .ods yet.

Formulas: OpenFormula writes references in brackets (`[.A1:.B2]`, `[$Sheet2.A1]`, `[$'My Sheet'.$A$1]`), separates arguments with `;`, writes inline arrays as `{1;2|3;4}`, and TRUE and FALSE as `TRUE()` and `FALSE()`. The `of:` prefix needs its namespace declared; without it LibreOffice reads every formula as Err:510. Newer functions: LibreOffice 24.2, converting an .xlsx, writes CONCAT, IFS and SWITCH as `COM.MICROSOFT.` names, DAYS, IFNA and XOR as they are, and the functions it lacks with their `_xlfn.` prefix. FormCel writes every function from the MS-XLSX list as `COM.MICROSOFT.` except those three, and reads all three spellings.

Checked (`tools/checks/odscheck.py`): every template written as .ods and read back shows 23,420 of 23,438 values the same (the rest are fraction and scaled formats written in the simpler form); LibreOffice 24.2 opens the same files and, saved as .xlsx, shows 23,360 of 23,438 the same; a LibreOffice-made .ods reads back with its formulas, sheet references, array constant, name, merge, link and formats.

### Notes, comments, history, versions, publishing and the live channel
- refers-to: app/services/collab.py :: Versions, Hub, render_sheet, log_edit, changes; app/routers/collab.py; app/services/store.py :: edit, collab_edit, set_protection, restore_version, publish_sheet, published; app/services/xlsx/protect.py :: notes_in, notes_out, sheet_in, sheet_out, book_in, book_out
- kind: explainer
- logged: v0.34.0 · 2026-10-21

The .fcel keeps `collab` (notes by `sheet:row:col`, comment threads, the edit log, the shares) and `protection` (the engine's lines per sheet and for the workbook). Notes are one text per cell with author and time; a thread has an anchor cell, messages, a status (open or resolved) and an assignee. An @name in a message is matched against the people the workbook has seen (authors, assignees, windows now open) and the box under the message can assign the thread to the first person named (MS-COMMENTS, G-COMMENTS; FormCel's reading is that people are local names, not accounts). Rows and columns inserted or deleted move the notes and threads, and sheet moves and deletes remap them.

Every edit sent to POST /cells is checked by the engine with the user name in `x-formcel-user` and refused with 403 and the engine's message, then logged with time, user, sheet, cell, before and after; GET /history filters by sheet and rectangle (MS-SHOWCHANGES, G-HISTORY). Versions are copies of the .fcel under `Versions/<id>/`, made after a save at most once every five minutes and on demand; a version can be named, previewed (the typed inputs of a sheet) and restored, and a restore first keeps the current file as `Before restore` and then records the restored file as a new version (MS-VERSIONS). The newest 200 versions are kept.

Publish and Share by link both make a token for a sheet and the engine serves `/published/<token>` as a read-only HTML table with the shown values and bold, italic, underline, colours and alignment; `?embed=1` drops the heading for an iframe, and revoking makes the token answer 404 (G-PUBLISH, G-SHARE). The page is served by this computer's engine, so a link reaches other machines only if they can reach it. Presence and edits go over a server-sent events stream `/api/workbooks/{id}/events` with a POST for the cursor; other windows on the same workbook get the edit, the cursor, and collab, protection and share changes. This is limited to one engine process, so it is partial real-time co-editing.

In .xlsx, notes are written and read as cell comments (openpyxl), sheet protection as `sheetProtection` with each action's flag inverted as the file format does and the legacy password hash, cell Locked and Hidden as cell protection, workbook structure as `lockStructure`, and Mark as final as the `_MarkAsFinal` custom property. openpyxl has no protected ranges, so named per-person ranges and comment threads stay in the .fcel and are not written to .xlsx.

### Data connections, scripts in files, REST API and the model endpoint
- refers-to: app/services/webdata.py :: fetch, tables_of, lists_of, xpath, import_*; app/services/hostcalls.py :: resolve, split_key; app/services/pquery.py :: run, step, sqlite_table; app/services/scheduler.py :: refresh, due, tick; app/services/aiclient.py :: update, turn, assist, cell_answer; app/services/ranges.py; app/routers/automation.py :: /api/host/resolve, /api/queries/run, /api/web/tables, /api/settings/*, /api/ai/assist, /api/extensions, /api/v1/*; app/services/store.py :: Book.auto, _write, _automation, set_automation
- kind: explainer
- logged: v0.34.0 · 2026-10-21

Fetching happens only here. `POST /api/host/resolve` takes the keys the engine is waiting on and returns an encoded answer and a note for each. Pages are fetched with urllib (http and https only, 15 seconds, 10 MB) and cached in memory for five minutes; `fresh` skips the cache. IMPORTHTML reads tables and lists with html.parser; IMPORTXML and FILTERXML run a small XPath subset (child and descendant steps, names, `*`, `@attr`, `text()`, `[n]`, `[@a='v']`, `[contains(@a,'v')]`, `[child='v']`) over a tree built from the page, since no XML library with full XPath is installed. IMPORTRANGE takes a FormCel workbook id instead of a URL (GS-IMPORTRANGE says URL; FormCel's reading) and reads the range from the open engine copy of that workbook. =[Book2.fcel]Sheet1!A1 is not parsed; IMPORTRANGE is the way to reference another file. There is no IMPORTFEED.

Queries (Power Query like) run in `pquery.py`: a source (CSV, JSON, a web table, a sheet range of a workbook, a SQLite SELECT) becomes a table and the steps run in order: use first row as headers (columns whose values all read as numbers become numbers, as Power Query's automatic type change does), remove or keep columns, rename, filter rows, change type, sort, group by with count, sum, average, min and max, remove duplicates, top rows. The SQLite file is opened read only with `PRAGMA query_only` and only a single SELECT or WITH statement runs. A saved query has a target sheet and cell; refreshing writes the result and blanks the rest of the previous result. `scheduler.py` wakes every 15 seconds, and a query with `every` minutes is refreshed in the engine process while it runs; the window refreshes the same queries itself while a workbook is open, so a workbook shows fresh data either way.

Scripts, queries, buttons and settings are saved in the .fcel zip: `automation.json` and one `scripts/ID.ts` per script. `PUT /api/workbooks/{id}/automation` stores them and `GET /api/workbooks/{id}` returns them as `automation`. Scripts only run in the window (a Web Worker), so there are no server side scripts and no server side triggers; time triggers run in the window while a workbook is open.

The model endpoint and the API token live in `settings.json` in the data folder, written with mode 0600, never in a workbook; GET /api/settings/ai answers without the key. `aiclient.py` speaks OpenAI compatible chat completions and the Anthropic Messages API with two tools, read_range and propose_cells; proposals come back to the window and nothing is written until the user applies them. =AI(prompt, range) sends the prompt and the range as tab separated text and answers #N/A with a note when no endpoint is set or it fails. FormCel bundles no model. ### gasrun.locked_down, gas_runner.js, jsfn.RUNNER, vbarun.spawn · scripts run with no file, process or network reach
- refers-to: services/gasrun.py (locked_down, _PERMISSION, OLD_NODE, run); services/gas_runner.js (after createContext); services/jsfn.py (call, RUNNER); services/vbarun.py (spawn)

Family ledger FB-043 (S0), found by the FAMILY_TEST_PLAN suite. The Apps Script runner and the JavaScript cell-function runner put the script in a Node `vm` context whose globals (Logger, SpreadsheetApp, CustomFunctions, console) are objects of the runner's own realm. `vm` is not a security boundary: `Logger.constructor.constructor("return process")()` reaches the host `Function`, which `codeGeneration: { strings: false }` does not cover (that option binds only the context's own realm), and from `process` the script had `mainModule.require` and `getBuiltinModule`: it read and wrote any file the person can, opened sockets, and could start programs. The only path it may read is the runner file itself (none for `-e`); file reads and writes, child processes, workers, native addons and `process.binding` are refused by Node. The permission model does not cover the network or signals, so before any script code runs the runners delete `fetch`, `WebSocket`, `EventSource` and the `-e` scope's `require`, `module` and `exports` from the global object and set `process.mainModule`, `process.getBuiltinModule` and `process.kill` to undefined; the runners captured `fs` and `vm` before that and use nothing else. `UrlFetchApp` still works: it asks the engine over stdout (`rpc fetch`), which applies its own address checks. The VBA runner interprets VBA (no `Open`, `Shell`, `Kill` or `CreateObject` reach the system; `Dir` and `Environ` return nothing) and gets the same flags as a second wall.
